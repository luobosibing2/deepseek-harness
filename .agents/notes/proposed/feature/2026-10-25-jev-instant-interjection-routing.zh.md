# Agent Note: Jev 插话分流与 DSH 响应中断

Status: proposed

[English](2026-10-25-jev-instant-interjection-routing.md) | 中文

## 问题

任务运行中的直接用户消息可能追加后续工作、补充当前要求，或否定当前方向。Jev 原来把纠正送到最近步骤，但 DSH 的普通 steering（中途引导）不会结束当前模型响应；用户指出关键前提错误后，旧响应仍可能继续。取消整个轮次会改变活动生命周期，不能表达同一轮次内的纠正。

分类需要当前任务和执行事实。额外模型总结会增加等待，还可能用不准确的解释替换用户原话。仅依赖近期输出也可能在有限上下文预算内挤掉原始任务。

## 提案

DSH 负责中断单次模型响应，Jev 通过公开 API 选择语义路由。Jev 将运行中的直接用户输入分为 `follow-up`、`steer`、`interrupt-steer` 或 `unknown`。有效即时纠正请求中断，再通过正常输入准入进入同一轮次的下一步。正常路径只调用一次分类，不调用总结或规划模型。

路由依据是消息在当前任务中的含义，不是语气或关键词。否定当前方向、改变关键前提或明确要求 agent（智能体）现在让出控制权，都可能支持 `interrupt-steer`。分类读取原始用户消息、近期已记录助手正文、必要工具事实和代码观察到的执行状态。读取和发送文字都有界，缺失材料不能变成虚构的任务摘要。

本地实现及确定性验证已完成。DSH 仍处于 fork 的[草稿 PR（Pull Request）#1](https://github.com/luobosibing2/deepseek-harness/pull/1)，尚未合并；官方仓库目前关闭 PR。Jev 的[配套 PR #54](https://github.com/luobosibing2/dsh-jev-plugin/pull/54)已包含验证过的 `main` 合入基线。作者于 2026-11-01 授权独立 subagent 验证，以及提交工作所需的提交、推送和创建 PR，包括这份完整规划记录。真实模型调用、包发布和目标分支合并仍不在该授权范围内。

### 范围与职责

范围包括 DSH 的公开响应中断、同轮次继续和流记录，以及 Jev 的三路分类、确定性上下文提取、有效判断应用和回执。Jev 使用公开扩展点，不读取或修改 DSH 的私有循环状态。

首版中断模型生成及模型请求失败后的重试等待。已启动工具、维护工作和整个活动轮次的原生取消规则保持不变。功能保留现有开关、输入身份、编辑和移除、人工 Retry/Cancel 及恢复行为，不承诺未经测量的延迟或分类准确率。

## 新增需求

- **REQ-JIR-01 — 响应中断**：DSH 提供区别于整个轮次取消的公开能力。有效即时纠正可中断模型生成或重试等待，即使模型尚未返回流分片，也不能等待下一分片才响应中断。该信号不取消已启动工具。没有可中断响应或重试等待时，请求不增加模型调用、不取消轮次，也不单独唤醒空闲 agent。
  - 验收：旧响应持续等待时，应用有效纠正使其模型请求信号取消；当前轮次及已启动工具的信号保持未取消。
- **REQ-JIR-02 — 同轮次继续**：DSH 先持久结算旧响应并结束当前步骤，再通过正常准入接收纠正，在同一轮次继续。不得记成用户取消整个轮次、绕过准入拒绝，或把纠正当作模型失败而重试旧上下文。
  - 验收：准入接受时，下一请求包含纠正原文且归属同一轮次；两个请求之间没有虚假的取消、空闲或新轮次。准入拒绝时不发新请求，保留原有拒绝语义。
- **REQ-JIR-03 — 中断内容**：按 DSH 的中断内容规则保留已生成的非空正文和推理（reasoning），排除该响应中尚未执行的工具调用。有内容时记录中断助手消息，否则记录助手尝试。一次响应只结算一次。下一请求通过正常历史派生及适配器投影使用记录；功能不恢复不可见的模型内部计算。
  - 验收：保留部分正文并标记中断；不执行流中的工具调用，不留下缺少结果的历史调用。空响应仅保留尝试记录。持久结算失败时，不发起依赖该历史的新请求。
- **REQ-JIR-04 — 快速分类路径**：代码读取、筛选和裁剪已有数据，不调用总结、规划或语义整理模型。稳定消息和任务下，Jev 正常只发起一次分类请求，只选择路由，不要求解释或改写。不按 token、流分片或定时器重判，也不在插话路径新增全 Session 日志扫描、仓库检索或文件内容读取。
  - 验收：稳定输入下观测到一次分类请求、零次辅助模型请求；后续分片不增加该次数。人工重试、消息编辑和确实过期的结果只在能关联实际原因时触发重判。
- **REQ-JIR-05 — 应用与复核**：Jev 成功分类后立即尝试有效中断，不等待下一次 pre-step。先复核消息身份、内容版本、所属活动和当前任务。旧判断不能作用于原活动结束后的新任务。响应已完成或工具已开始时，仍有效的纠正按最近正常步骤投递，不声称模型实际被中断。
  - 验收：旧响应仍等待时完成分类，立即请求中断。分类完成前移除或编辑消息、原生停止活动，都会阻止旧结果中断或恢复工作。
- **REQ-JIR-06 — 可观察记录与集成**：区分路由选择、中断请求、实际响应收束及原始消息准入。判断为中断不等于模型收到纠正或工具停止。模型可见内容仍可从 DSH Session 记录重建；Jev 判断和执行回执沿用现有记录。原始输入只准入一次。
  - 验收：Session 和 Jev 记录能识别实际动作，不在不可中断阶段虚报成功。Web transcript（文本记录）和两种 SDK 显示同轮次继续，不提前宣告整个活动结束。

## 修改需求

- **REQ-JIR-07 — 三路语义分类**：
  - 之前：启用分流时，将运行中直接用户消息分为 `correction`、`queue` 或 `unknown`；`correction` 在最近步骤接收，不取消活动模型请求。
  - 提议行为：仍仅分类启用分流的活动根 agent 的直接用户消息，包括原本通过 queue 或 steer 提交的消息。`follow-up` 是当前任务完成后的后续工作；`steer` 补充当前任务，但没有证据要求结束眼前步骤；`interrupt-steer` 表示当前方向或关键前提失效，或用户明确要求立即让出控制权。上下文不足时返回 `unknown`。语气、单个否定词和引用材料不能独自决定路由。后续事项与即时纠正共存时，纠正优先；完整原文只投递一次，不拆成多个任务。
  - 验收：分析错误仓库时，“麻烦先停一下，仓库看错了”选择 `interrupt-steer`；“做完赶紧补测试”选择 `follow-up`；不影响当前分析的最终展示要求选择 `steer`。相同表达在不同任务上下文中可以得到不同路由。
- **REQ-JIR-08 — 确定性分类上下文**：
  - 之前：请求主要包含新消息、附件类型、按末尾优先选取的历史正文、可选 Goal 和规则。历史可能挤掉轮次原始要求，也没有明确的实时执行阶段。
  - 提议行为：包含新消息原文、当前轮次直接用户要求及已准入修改、可选活动 Goal、近期可用助手正文、必要工具事实和代码观察到的阶段。内容直接来自原消息、Session 派生数据、已有投影或运行事件，保留来源身份和顺序。不总结任务、不猜测隐藏 thinking，也不为分类新增逐 token 正文重建。工具事实只含最近相关名称、必要参数和执行状态，不发全量工具日志；参数是事实，不是用户指令。至少区分模型响应、模型重试等待、工具执行和其他阶段。无法取得状态时标明缺失，不虚构。
  - 验收：请求事实可追溯至用户原话和已有记录。主模型尚无输出时，任务和执行阶段仍可用于分类。预算能容纳任务要求时，长输出不能挤掉要求；附件或前提缺失时不得编造材料。

## 删除需求

无。既有 follow-up、steer、inject 及整个轮次取消继续可用。Jev 的两种可执行分类扩为三路；历史记录保留原义并继续可读，不重判旧输入。

## 保持的行为

- 分流沿用现有开关，默认关闭。关闭时保留 DSH 的原始提交行为。
- 空闲新任务、Goal 消息、插件通知和 subagent 消息不进入自动三路分类。
- 保留消息身份、原文、附件和来源。编辑使旧分类失效；移除只取消该输入。相同投递目标按到达顺序处理；`steer` 与 `interrupt-steer` 共用最近步骤目标。不按分类完成顺序重排，不合并相同文本的不同消息。
- 原生停止或 dispose（资源释放）仍取消活动。响应中断不得清空无关排队输入、取消 Jev 生命周期或授予新工具权限。
- 保留人工 Retry/Cancel、关闭期间处理及恢复：取消分类不投递输入；关闭后重试先重新开启；已发出且成功的判断只在消息和活动仍有效时采用；恢复不自动重判或投递未完成的历史输入。
- 原有拥有者继续管理权限、工具准入、沙箱、请求失败及 Goal。即时纠正只改变响应结束和输入接收的时机。

## 输入、默认值、顺序与优先级

新文字沿用 `messageChars` 限制，默认 24,000 字符。空文本或超限文本不得截断成另一条可分类消息。附件只提供可用类型和内容可用性；本功能不新增附件读取或视觉模型请求。

分类上下文沿用 `contextChars`，默认 12,000 字符。任务、Goal、助手和工具文字共享该预算；新消息文字另受 `messageChars` 限制。固定规则、标识及状态字段不计入上下文文字预算。这是字符上限，不是 token 计量。保留配置的正整数范围，不另加一组部署调参项。

优先保留当前用户要求：先选最近已准入修改和轮次起始要求，再选当前轮次其他要求、活动 Goal、近期助手正文及必要工具事实。各类选中材料按原始顺序呈现，标明裁剪和缺失。无法容纳的文本不以摘要替换。丢失信息足以改变路由时返回 `unknown`。轮次若以“继续”等依赖前文的消息开始，可在同一预算内补充可用前文，不虚构缺失任务。

后来的直接用户修改帮助识别当前有效要求；引用或转述的外部文字不是新用户授权。原生停止、输入移除和活动结束优先于旧异步判断。响应完成本身不表示任务改变，不得因此无条件再调一次分类。

消息到达时准备一份分类输入，正常路径不随每个流分片刷新。人工重试或确实过期的判断使用当时有效事实。分类后 Jev 仍检查运行状态，决定能否应用中断请求。

## 失败与回退

- `unknown`、必要文本缺失、无法解释的附件及分类传输或协议错误保留人工 Retry/Cancel。不静默选择任何可执行路由，也不切换模型。
- DSH Host 缺少公开能力时明确失败。不用 cancel 加重启伪装支持。支持版本声明必须反映实际验证版本。
- 分别处理响应中断和真实模型失败。有效即时纠正不重试旧请求；没有中断的真实失败保留现有恢复规则。并发原生取消优先。
- 持久记录失败时停止依赖请求并报告；不可重建内容不得进入模型。辅助回执失败不重发输入，也不重复中断。
- 没有模型响应或重试等待接受中断时，仍有效的纠正进入最近可用步骤。不取消已启动工具，不承诺提供商计算或计费同步停止。

## 端到端传递

直接用户输入进入现有 inbox，保留身份和编辑能力。Jev 组装有限事实并分类。`follow-up` 等待后续轮次；`steer` 等待当前轮次最近步骤；有效 `interrupt-steer` 调用 DSH 公开响应控制，再通过同样的正常准入接收原文。

DSH 负责响应结算及历史；Jev 不补写替代主模型输出，不虚构工具结果。响应中断不能绕过准入、重复插入用户消息或触发整个轮次完成监督。模型执行仍由正常循环准备和已配置适配器负责。

复用可用的原始任务、状态和已记录正文。新增 Session 派生状态遵循仓库投影机制：不使用已废弃的同步全历史读取器，不因缓存缺失在插话路径扫描全日志。有界运行状态随 agent 生命周期释放。

## 公开 API 与消费方

实际公开 API 是 `Agent.interruptResponse(): boolean`。`true` 表示可中断响应或重试等待接受了本次请求，不表示模型已经收到用户消息。能力区分响应中断和整个轮次取消；记录可显示响应是否因中断实际收束。这里保存已选定 API，不把早期示意签名另立为要求。

Jev 保留离散路由选择，增加即时纠正语义，正常路径不要求解释。传输字段由原判断协议拥有；示例 JSON 不构成新公开 API。Jev 继续独立发布，依赖 DSH 公开能力。受影响声明的消费方须一起更新。

复用现有中断助手消息与尝试记录，不因路由偏好单独提升 Session 格式。实际持久类型变更仍须遵守仓库已发布数据审查和声明规则；忽略未知事件不能替代兼容性。Jev 历史路由记录保留原义。

同步受影响的功能说明、API 文档和 transcript。循环变更同步架构及 TypeScript/Python SDK 预期输出；新增模型或用户可见行为须有无密钥 Session 快照。可见分流文字使用原有本地化机制。本提案不新增按钮、设置页或快捷键。

DSH 的 [steer、cancel 和响应控制](../../../../packages/core/agent-loop/src/agent.ts#L183)、[中断内容组装](../../../../packages/llm/llm/src/assembler.ts#L169)、[DeepSeek 请求取消](../../../../packages/llm/llm-deepseek/src/adapter.ts#L142)、[轮次投影](../../../../packages/core/agent/src/projection.ts#L21)及[响应事件](../../../../packages/core/agent/src/runtime-types.ts#L391)分别拥有执行与已记录事实。Jev 的[路由](https://github.com/luobosibing2/dsh-jev-plugin/blob/codex/jev-instant-interjection-routing/packages/jev/src/interjection.ts)和[上下文投影](https://github.com/luobosibing2/dsh-jev-plugin/blob/codex/jev-instant-interjection-routing/packages/jev/src/interjection-context.ts)链接指向配套分支，不是 DSH 发布依赖，也不表示任一功能分支已经合并。

## 相关决定

针对活动记录的定向复核未发现需要替换或部分取代的拥有者。[Follow-up 入队和自有运行区间](../../implemented/architecture/2026-07-30-followup-enqueue-and-owned-runs.zh.md)仍区分消息准入与自有活动结果。[区分上下文注入和轮次执行](../../implemented/architecture/2026-07-24-separate-context-injection-from-turn-execution.zh.md)仍拥有独立消息和输入准入。响应中断不改变两项决定。[Composer 链选取的语义阶段](../architecture/2026-08-08-semantic-composer-chain-phases.zh.md)管理 UI composer 选择，继续独立适用。这些记录保持活动状态，本提案不归档或改写它们。

## 考虑过的替代方案

**只增加路由，继续普通 steer。** 能区分意图，但仍等待当前响应结束，不能解决即时纠正后的等待。

**取消后重启轮次。** 可复用现有 API，但会引入活动取消和新轮次，改变输入保留、监督和 SDK 生命周期，无法保留同轮次纠正。

**先用另一模型总结任务和执行状态。** 可以缩短分类文字，但增加模型等待和摘要错误。原消息与已有事件已提供首版所需事实。

**复制 Codex WebSocket 中断协议。** 区分响应抢占和轮次取消有参考价值，但不能假定 DeepSeek HTTP/SSE（Server-Sent Events）或每个适配器支持该传输协议。因此复用 DSH 的取消能力。

**同时取消已启动工具。** 会增加响应中断之外的工具取消、外部副作用处理和后台进程管理。

## 验收标准

上述要求与下列场景定义完成条件。特别是无新分片也能中断、同轮次接收纠正、正文只结算一次、未执行工具保持未执行，以及正常路径没有辅助模型调用。整个轮次取消、准入拒绝、未知分类和恢复保持原义。确定性执行证据与真实分类质量分别报告。

| 场景 | 给定 | 当 | 必须结果 | 需求 |
|---|---|---|---|---|
| 无输出响应 | 模型请求持续等待 | 有效即时分类完成 | 不等新分片就取消旧请求；准入纠正并在同轮次继续 | REQ-JIR-01, REQ-JIR-02, REQ-JIR-05 |
| 正文期间纠正 | 响应结束前已有部分正文 | 路由为 `interrupt-steer` | 旧正文只结算一次并标记中断；下一请求使用正常历史 | REQ-JIR-02, REQ-JIR-03 |
| 工具参数仍在生成 | 响应含未执行工具调用 | 中断响应 | 不执行，也不留下缺少结果的历史调用 | REQ-JIR-03 |
| 重试等待 | 失败模型请求正等待重试 | 有效即时纠正到达 | 结束等待，不重发旧上下文；同轮次准入输入 | REQ-JIR-01, REQ-JIR-02 |
| 工具已启动 | 工具执行中 | 路由为 `interrupt-steer` | 工具继续；最近步骤投递，不声称工具停止 | REQ-JIR-01, REQ-JIR-05, REQ-JIR-06 |
| 后续任务 | 用户说“这个做完以后，赶紧补一份说明” | Jev 分类 | 选择 `follow-up`；不因语气急切中断 | REQ-JIR-07 |
| 当前补充 | 当前分析仍有效；要求最终结论带兼容性限制 | Jev 分类 | 选择 `steer`；响应继续，最近步骤准入补充 | REQ-JIR-07 |
| 客气的前提纠正 | agent 分析错误仓库；用户说“麻烦先停一下，仓库错了” | 分类有效 | 选择 `interrupt-steer` 并立即请求中断 | REQ-JIR-05, REQ-JIR-07 |

## 非目标

- 不取消已启动工具、不撤销副作用、不管理外部后台进程。
- 不要求每个 DSH 提供方支持 Codex 的 `response.interrupt` WebSocket 协议，不新增连接复用，也不承诺服务端取消。
- 不新增模型摘要器、辅助规划 agent、逐 token 分类、全历史索引或仓库检索。
- 不新增独立的自然语言整任务停止执行通道。原生停止继续可用，用户原始撤回或停止要求仍送主模型。响应中断本身不授权继续旧任务。
- 不在本提案中重构无关 Jev 功能、扩大自动审批、Goal 管理或 subagent 消息范围、修改个人配置、安装 profile、发布包或合并目标分支。

## 风险

语义分类可能误中断，或缺少判断所需上下文。有界输入和 `unknown` 能暴露事实不足，不能证明分类正确。真实模型分类质量和生产延迟未验证；本提案没有实测准确率或延迟保证。

提供商计算可能不同步停止，已启动工具继续运行。响应控制改变后续推理和准入，不能撤销已发生动作，也不能恢复不可见模型计算。

Jev 独立发布。支持的 DSH 版本必须包含公开响应控制能力并经过验证。不能用私有状态或 cancel 加重启掩盖依赖缺失。未决产品问题为零：职责分工、三路语义、同轮次继续、响应和重试范围、原始事实上下文及正常一次请求已确定；目标分支合并和发布仍是独立动作。
